# 自动音频恢复

[English](audio-recovery.md) | 简体中文

Agent 独立于播放器轮询观察配置的 DAC。Spotify 或 DLNA 服务存活不代表 USB 输出可用，状态分别报告硬件可用性、输出健康和恢复阶段。

## 硬件错误

| 原因 | 含义与处理 |
| --- | --- |
| `dac_unconfigured` | 在配置中选择 DAC。 |
| `dac_missing` | 找不到匹配 USB 设备，检查电源和连接。 |
| `dac_not_ready` | USB 存在但播放/控制节点不完整，等待枚举或查看内核 USB 错误。 |
| `discovery_failed` | 观察失败，硬件可用性未知。 |
| `service_failed` | 服务修复失败，查看有界诊断。 |
| `output_stalled` | 宽限后播放音源仍无物理输出，已请求分阶段修复。 |
| `maintenance_busy` | 更新/配置持有共用维护锁，恢复等待中。 |
| `recovery_exhausted` | 自动重启预算耗尽，检查原因后认证重试。 |

网页持续显示输出错误。认证状态接口包含 `output.hardware`、`output.health` 和 `output.recovery`。硬件缺失撤销输出所有权；软件无法修复未接线、未通电 DAC 或持续 USB 协议故障。

## 修复策略

连续三次间隔一秒的稳定观察后开始服务恢复。Agent 重建 MPD 旧映射并清理受影响启动限流，再修路由。只有无法分配 sink 才重启 WirePlumber。持续输出停滞或局部修复失败时，升级为重建专用账号 PipeWire/Pulse 会话及可选播放器。Agent 保持运行，保留配置/会话文件和不可变镜像。

滚动十分钟最多三次自动破坏性尝试，退避 5/20/60 秒，每次期限 120 秒。最近三次时间戳跨 agent 重启保留。硬件缺失不反复重启音频栈。手动重试允许一次有限尝试，每分钟一次。恢复不重置 USB 控制器、不改固件、不重启宿主。

恢复完成后无 owner 且保持暂停，请重新请求播放。重建已有 DAC sink 时保留软件音量；读不到有效音量时按已有宿主策略/配置处理，不自动改为单位增益。完整会话重建影响同账号其他音频客户端，因此要求专用服务账号。

修复时已有播放器流停放在 standby。真实 DAC 保持为新建流的默认目标，但 sink 挂起；新的播放请求经过正常仲裁后解除挂起并取得所有权。在已验证的 PipeWire 版本上，恢复后继续默认指向 standby 可能使 Soloist 首个新流无法连接。

所选 DAC 使用 PipeWire Pro Audio 配置，指向 ALSA `hw` PCM。模拟 `front` 路径可能触发 ALSA 转换，PipeWire 显示 44.1kHz 本身不能证明 USB 实际为 44.1kHz。修复选择硬件配置时保留增益/静音，在音源暂停时协调旧 48kHz standby 节点，并先迁移流再解除 DAC 挂起。冷启动和交接后应验证实际 USB 反馈。

## 验证

运行 Linux 单元测试和[测试指南](../testing/README.zh-CN.md)的集成步骤。确定性测试覆盖设备缺失/部分枚举、代次、重试持久化和路由故障。硬件验收还须验证真实拔插、断电和恢复后的播放。软件测试通过不证明线缆健康或听感质量。
