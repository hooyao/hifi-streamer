## Clock workaround

This board/kernel combination can report CPU PLL lock failures during frequency changes and produce discontinuities even in ALSA direct playback. A fixed 1.2GHz profile is a qualified workaround, not a root-cause kernel fix or a general ARM default.

The supplied `m401a-fix-clock.sh` and `m401a-audio-clock.service` fix cpufreq min/max. Review available frequencies and the unit's account dependency before installing:

```sh
sudo install -m 755 docs/testing/m401a-fix-clock.sh /usr/local/sbin/m401a-fix-clock
sudo install -m 644 docs/testing/m401a-audio-clock.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now m401a-audio-clock
```

Check current/min/max frequency after full reboot. Disabling the service alone does not restore current limits; restore recorded limits explicitly or reboot after disabling.

## Coverage and limits

The profile covers PCM 44.1/48/96kHz, FLAC, DSD64 DoP, Spotify 44.1kHz, handoff, USB hotplug and service restart/reboot. Long-duration acceptance remains a separate test gate. It does not certify every kernel, DAC, DSD rate or Native DSD.

See [test procedures](README.md) and [clock troubleshooting](../debugging/troubleshooting.md). Diagnostic scripts in tests restore temporary CPU limits on exit.
