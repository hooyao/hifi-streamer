# M401A硬件配置

## 验证目标

Android 设备配置音频运行环境前，参阅 [Armbian U 盘安装参考](armbian-install.zh-CN.md)。

| 项目 | 配置 |
| --- | --- |
| 板型 / SoC | M401A、Amlogic S905L3A |
| 资源 | 约2GiB内存、16GB eMMC |
| 系统 | Armbian/Debian Bookworm ARM64 |
| 内核 / DTB | 6.12.109-ophub / meson-g12a-s905l3a-m401a.dtb |
| 容器运行时 | Podman4.3.1、crun |
| 音频服务 | PipeWire0.3.65、WirePlumber0.4 |
| USB DAC | Topping DX5 II、VID/PID152a:8750 |

在目标设备解析账号ID、运行目录、地址和卡号；这些值不属于产品配置契约。

## 时钟规避方案

该板型/内核组合可能在调频期间报告CPU PLL锁定失败，连ALSA直出也出现断续。固定1.2GHz是经过验证的规避方案，不是内核根因修复，也不是通用ARM默认设置。

`m401a-fix-clock.sh` 与 `m401a-audio-clock.service` 固定cpufreq min/max。安装前核对可用频率及服务单元的账号依赖：

```sh
sudo install -m 755 docs/testing/m401a-fix-clock.sh /usr/local/sbin/m401a-fix-clock
sudo install -m 644 docs/testing/m401a-audio-clock.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now m401a-audio-clock
```

整机重启后检查current/min/max。只停用服务不会恢复当前限值，需显式恢复已记录的限值，或停用后重启。

## 覆盖与限制

覆盖PCM44.1/48/96kHz、FLAC、DSD64 DoP、Spotify44.1kHz、交接、USB热插拔和服务/整机重启。长时间验收仍是独立测试门槛，不认证所有内核、DAC、DSD采样率或Native DSD。

启用恢复监督器后，DX5 II 断电重启产生新 USB 枚举但保留配置身份，重新出现后约 13 秒自动恢复暂停就绪，随后 PCM/FLAC/DSD64 DoP 和 Spotify 交接测试通过。这不认证持续电气 USB 故障的恢复；无 DAC 启动及完整故障注入矩阵仍是独立验收项。

参阅[测试步骤](README.zh-CN.md)及[时钟排障](../debugging/troubleshooting.zh-CN.md)。tests中的诊断脚本退出时恢复临时CPU限值。
