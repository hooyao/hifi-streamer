# Design

[English](design.md) | 简体中文

## Context

参阅[提案](proposal.zh-CN.md)及[需求](translations/zh-CN/specs/audio-recovery/spec.md)。当前 Runtime 根据声卡存在/卡号判断连接，在状态锁内同步部署，并将适配器播放状态视作输出健康。无 DAC 冷启动与热插拔行为不一致，同卡号重新枚举可能保留旧映射。路由层会压制释放错误并可能停止 Soloist，但不监督其恢复。仅重启 WirePlumber 可能恢复 sink 而留下未连接的播放器流，必要时需重建完整会话。USB `-71` 证明协议失败，不证明具体线缆/控制器根因。

## Goals / Non-Goals

**Goals:** 可恢复故障后自动恢复基础设施，准确报告错误、保留音量/会话数据，未来适配器也可使用且不把专用命令放进仲裁器。

**Non-Goals:** 修复物理缺失/损坏 DAC、用电平推断听感、调整 CPU/内核/USB 电源、重启宿主、无人值守恢复声音或修复解码/媒体服务器错误。

## Decisions

### 独立于播放器观察硬件

新增 Runtime 使用的轻量恢复模块。硬件每秒观察配置 USB 身份、当前枚举实例（sysfs 总线/设备身份）、播放节点及卡号/PCM 映射；通过节点设备号/inode 识别映射变化。区分 unconfigured、missing、enumerating、ready、unknown，发现失败不等同缺失。消失或枚举实例变化时更新代次，即使卡号相同；连续三次稳定观察后才修复服务。内核日志仅作为有界辅助诊断，不能依赖日志权限/环形缓冲作为主要触发。

硬件观察与可能缓慢的适配器轮询分离，缓存带时间戳的适配器/路由快照，过期观察标记 unknown，避免 Soloist 超时阻塞五秒内缺失报告。

### 增加控制平面输出健康

兼容性新增 `output.hardware`、`output.health`、`output.recovery`：所选/观察身份、可用性、阶段、原因码、次数、下次重试、认证重试资格。已有 owner/state 保留。原因包括 `dac_unconfigured`、`dac_missing`、`dac_not_ready`、`discovery_failed`、`route_missing`、`service_failed`、`output_stalled`、`maintenance_busy`、`recovery_exhausted`。即使适配器播放/健康，仍按最新硬件观察发布错误。网页显示持续输出提示及分阶段操作说明。重试端点使用已有登录/Origin/CSRF，不接受 shell/服务参数，也不将缺失设备伪装成软件可修复。

检查实际发现的 PCM 播放端点。播放 owner 有十秒启动/切换宽限，之后连续三次路由/PCM 失败才修复。Spotify 检查实际流 sink/link 是否指向所选 DAC；DLNA 检查直出与 PCM 运行。静音电平无关，正常闲置挂起或暂停/停止不触发恢复。无路由故障证据的解码/HTTP 错误留在音源层。就绪仅代表基础设施可用，不代表正在播放或 bit-perfect。

### 在状态锁外串行执行有限恢复

单个后台恢复 worker，按设备/配置代次取消工作。短锁发布状态，子进程有明确超时且在 Runtime 状态锁外执行；单一待处理请求合并重复观察。物理断开立即撤销 owner，通过有界控制暂停，无法安全控制时才停止播放器。保持 upmpdcli 和网页/控制服务可用；持有维护锁时不递归进入仲裁器。

恢复、配置服务生成和更新（含已有事务）共用文件锁，完整破坏性事务期间持有，取得后复核代次/配置。配置重新生成也移出状态锁并发布 applying 状态。维护忙时等待且继续显示硬件错误；更新期间消失仍撤销输出，取消/回滚由更新事务负责。恢复不改变镜像引用。

### 按需逐级恢复

| 阶段 | 触发与操作 | 验证 |
| --- | --- | --- |
| 等硬件 | 缺失/不完整 DAC 不反复重启音频栈 | 连续三次稳定可用观察 |
| 协调服务 | 稳定返回后暂停音源、重建受影响 MPD 映射、显式 reset-failed/start、关闭旧适配器传输并生成新实例 ID | MPD 控制/standby 可用；配置音源响应或单独报错 |
| 修路由 | USB/ALSA 正常但 sink 缺失，重启一次 WirePlumber；sink 存在但流未连接时重建对应可选播放器并重新分配路由，不播放 | 所选 sink 存在且可分配路由 |
| 重建会话 | 小范围修复失败后静默音源、停止 Pulse 可选播放器、重启该账号 PipeWire/Pulse/WirePlumber、等待 socket/sink、重启合格播放器、更新适配器与 standby | 必备 DLNA 和输出路由就绪，可选错误隔离 |
| 人工介入 | 预算耗尽或硬件持续不可用 | 持续可操作错误及认证重试 |

完整会话重建影响专用账号其他音频客户端，所以先做已验证的小范围修复，不在每次热插拔时直接执行。无需重启 agent；监督器必须继续观察自己的修复。可选音源未认证或 exit-10 过期不是宿主栈故障。清理服务失败前检查 Result/限流，不能每秒 reset-failed 绕过 systemd 保护。

一次尝试为含有限升级阶段的破坏性事务；重试延迟 5/20/60 秒，滚动十分钟最多三次，每次最多一次完整会话重建，事务总期限 120 秒。私有状态原子保存最近三次时间戳，避免重启 agent 补满预算；记录启动身份，保守处理时钟变化。USB 抖动期间保留全账号预算及每枚举实例阶段状态，新稳定实例可重新考虑但不能绕过全局预算。健康 60 秒后重置成功阶段，预算时间戳保留至过期。认证手动重试可允许一次有限尝试，60 秒限频，不重启/重置硬件。

### 恢复暂停就绪并保留设置

修复前保存逻辑状态/代次，缓存 playing 不能作为恢复播放授权。暂停/停止合格音源，重建宿主会话时保留配置启动音量和当前软件音量，通过新适配器 ID 清除旧意图/seen 状态。音量快照仅恢复同一所选 DAC，不自动写 0dB。保留配置、API key、队列和登录会话；端点可用后才重建映射。就绪时无 owner，新控制器播放请求经过正常仲裁；恢复前/恢复中未完成请求取消，网页提示重新播放。

### 按真实故障边界测试

单元测试注入硬件/端点、假时钟、子进程结果与路由图，覆盖冷启动缺失、部分枚举、发现失败、同卡号替换、恢复中消失、旧工作、服务失败重置、播放器停止、sink 缺失/流未连接、健康闲置/静音播放、音源错误、预算持久化、可选音源缺失/过期及锁竞争。模拟修复阻塞时验证状态仍响应。

宿主集成注入失效路由/播放器状态及 systemd 限流，验证无需手动重启服务的分阶段恢复，再测 DLNA 44.1/48/96kHz、FLAC、DoP 与 Spotify 44.1kHz 交接。手动低硬件音量验证 DAC 拔插/断电。可注入正常 USB 移除，不制造电气 `-71` 或短接。硬件不枚举必须报错，不能伪造恢复成功；听感仍手动验收。报告保存在忽略目录或 CI 产物。

## Risks / Trade-offs

- 误判停滞 → 宽限、重复观察和物理路由验证，不把静音/内容错误当作音频栈故障。
- 同账号音频中断 → 要求专用账号且优先局部修复。
- 控制器意图竞争 → 代次失效及暂停就绪基线；恢复期间请求需重试。
- 无限抖动/崩溃 → 持久全局预算、有界日志及明确人工状态。
- 维护期间设备消失 → 立即撤销输出，共用锁防止冲突服务变更。

## Migration Plan

先增加监督器、兼容 API 与受保护重试端点及确定性测试，再集成部署/更新锁和网页提示。故障注入与真实拔插验收通过后才默认启用自动破坏性修复。保留当前镜像引用/数据布局。回滚恢复旧 agent/web 及服务生成，旧版可忽略无凭据恢复历史。不能用 mock 测试勾选硬件验收。
